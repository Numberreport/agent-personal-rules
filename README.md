# 通用智能体个人规则

用于自己的多台电脑和不同智能体。AGENTS.md 是唯一的规则源文件，内容不绑定某个产品。仓库公开，只保存规则和使用说明。任何电脑均可免登录下载；提交修改仍需写入权限。

## 接入方式

直接下载本仓库，无需登录 GitHub。

每个智能体都需要确认自己的规则入口。支持 AGENTS.md 的工具，按其实际加载位置接入；使用其他规则文件名的工具，将同一份内容链接或复制到它的规则入口；只提供自定义指令设置的工具，将内容填入设置。

AGENTS.md 这个文件名不能保证所有智能体自动读取。接入后应根据工具文档或实际加载信息验证是否生效。工具自身的规则优先级和长度限制仍然适用。

已有规则先备份并比较，不直接覆盖不同内容。不要把账号、密钥或其他登录配置上传到仓库。

用文件链接接入的，会自动使用更新后的内容；复制文件或填写自定义指令的，更新后需要再同步一次。

## Ekko Studio

Ekko Studio 的全局入口是「设置 → 全局 Prompt 指令」，对应配置文件 `~/.hermes-web-ui/.ekko/config/config.json` 里的 `prompt.instructions`。把 AGENTS.md 全文作为一个条目填入，它附加到每次 Ekko 运行。

内容从 GitHub 原文取，不要从本机副本复制：`https://raw.githubusercontent.com/Numberreport/agent-personal-rules/main/AGENTS.md`。Windows 下本地克隆是 CRLF 换行，粘贴过去会出现肉眼看不出的差异。

这是复制式接入，不是文件链接。改完 AGENTS.md 后要重新填一次，或调用一次接口：`PUT /api/ekko/config`，body 为 `{"config":{"prompt":{"instructions":["<全文>"]}}}`。判断是否同步：回读的内容与 GitHub 原文算 sha256，一致即同步。

## 修改规则

按 AGENTS.md“规则维护 / 修改规则”执行。先形成改稿，独立审查通过并经用户确认定稿后，才修改正式文件、提交和推送。

开始修改前检查本地状态；有未提交修改时先保留并说明，不擅自提交、丢弃或覆盖。确认工作区干净后，运行 `git pull --ff-only`。如果拉取带来了影响改稿的变化，应基于最新原文重新审查和确认。

提交时只包含本次已确认的改动；需要同步修改说明或章节引用时，一并核对并提交。推送成功后，按“同步已有规则”同步到当前智能体。遇到冲突时停止并说明，不强制覆盖。

## 审查标准

凡独立审查（本仓库规则改稿、项目框架及其他方案），统一按下列四项，以用户确认的修改目标为依据；不按对象另立标准。此处只定审查标准，不规定各对象自己的修改流程。

- 简洁：只保留必要内容，不重复、不绕弯，不遗漏关键条件。
- 易懂：用常用词和短句，让使用者容易理解。
- 无歧义：意思明确，与现有规则或既有约定不冲突。
- 可执行：明确什么情况下做什么、怎样算完成；必要时说明做不到怎么办。

## 审查模板

将下面的模板和材料交给不带起草过程的只读新会话或智能体。不要附上起草者的自评。审规则改稿、框架或其他方案时都用此模板，按实际对象填写「原文」和「改稿」。

```text
请独立审查下列改稿，只读，不修改文件、不提交或推送。

修改目标：
[用户已确认的目标和范围]

原文：
[修改前的内容]

改稿：
[准备采用的完整内容]

相关现有规则及配套说明：
[可能影响判断的规则和说明；没有则注明无]

请按简洁、易懂、无歧义、可执行四项检查：必要内容是否保留，表达是否易懂且明确，是否与现有规则或既有约定冲突，是否知道何时做什么以及怎样算完成。

给出“通过”“需要修改”或“无法判断”的结论，简要说明检查范围。
发现问题时，指出具体位置、原因和修改建议。
缺少影响结论的材料时说明缺什么，不猜测通过。
仅影响个人措辞偏好的建议单列，不作为不通过的理由。
```

## 同步已有规则

用户说“更新规则”时，默认按本节执行。找到本地仓库；没有则下载。确认没有未提交修改后，运行 `git pull --ff-only`，再按各工具实际支持的方式同步 AGENTS.md。

同步前比较已有规则；内容不同或发生冲突时，先说明差异，不强制覆盖。只同步规则，不上传账号、密钥或其他本地配置。

完成后核对内容，并说明是否需要重新加载或新开会话。无法确认已加载时明确说明。此仓库未设置自动同步。

## 反馈

按 AGENTS.md“规则维护 / 反馈问题”执行：使用中发现问题、而用户没有当场要求修改时，先征得用户同意，再到本仓库 Issues 按“规则反馈”表单提交。

不写账号、密钥、个人信息或项目隐私。不能使用 GitHub 时，将反馈内容交给用户转交。
